# Technical Design: Block INSERT Writing instead of Exploding (Non-exploding Stamps)

> Design reference for the standalone markup exporters. Normal Save/Save As
> already preserves stamped INSERT entities through `DocumentDXFWriter`.
> The primitive-only markup export limitations remain documented in [README.md](README.md#save--export).

## 1. Overview & Context

In NovaCAD, the block stamp tool allows users to pick an existing block symbol (such as a factory station, layout device, or standardized marker) and place copies of it as markups/stamps. 

Historically, there was an inconsistency in how these stamps were handled and exported:
1. **In-memory placement:** When a user places a block stamp using the Stamp Tool in the UI, `ContentView.placeStamp(at:)` uses `BlockEditor.insert(...)` to add a true `INSERT` entity (a block reference) directly into the live `EntityStore`. This avoids exploding the block into primitive lines in-memory, preserving the original block reference and hierarchy.
2. **On-disk export (DXFWriter):** When exporting user markups via `DXFWriter.swift` (specifically `DXFWriter.writeMarkupDXF` and `DXFWriter.writeMergedCopy`), the exporter reconstructs `[DrawnEntity]` from the store using `MarkupStore.drawnEntities(in:layerId:)`. However:
   - `DrawnEntity` does not have a representation for `INSERT` (block references) — it only has representations for basic primitives (`line`, `polyline`, `circle`, `arc`, `rect`, `text`).
   - Consequently, when retrieving live entities via `MarkupStore.drawnEntities` to feed `DXFWriter`, those `INSERT` references are either ignored, or they were previously flattened/exploded into line primitives.
   - This prevents external downstream tools (such as spatial planners or other CAD consumers) from receiving clean, semantic block symbols (`INSERT` records) in exported DXFs, forcing them to parse raw line segments.

### Goal
The goal of this design is to support true **block INSERT writing (non-exploding stamps)** in the DXF output generated by `DXFWriter.swift`. This preserves block references in exported DXFs so that downstream applications can locate specific stamps and symbols cleanly instead of receiving exploded line segments.

## 2. Technical Proposed Changes

To achieve non-exploding block INSERT writing, we must extend `DrawnEntity` and `DXFWriter` to handle block references natively.

### 2.1 Extend `DrawnEntity.Shape`
First, we must extend `DrawnEntity.Shape` (located in `Sources/CADCore/DXFWriter.swift`) to support `INSERT` entities.

```swift
public enum Shape: Equatable, Sendable {
    case line(a: CGPoint, b: CGPoint)
    case polyline(pts: [CGPoint], closed: Bool)
    case circle(center: CGPoint, radius: CGFloat)
    case arc(center: CGPoint, radius: CGFloat, startDeg: Double, endDeg: Double) // CCW
    case rect(a: CGPoint, b: CGPoint)
    case text(position: CGPoint, height: CGFloat, string: String)
    // New block insert representation:
    case insert(blockName: String, position: CGPoint, scale: CGPoint, rotationDeg: Double)
}
```

We must also update the helper functions on `DrawnEntity` such as `translated(by:)` and `transformed(by:)`:
- **`translated(by:)`**: Translates the insertion `position` of the block.
- **`transformed(by:)`**: Transforms the insertion `position` and scales/rotates the block parameters appropriately (combining rotation angles and scaling factors).

### 2.2 Update `MarkupStore.swift` to Reconstruct `insert` Shapes
In `MarkupStore.drawnEntities(in:layerId:)`, when looping over entities in the live `EntityStore`, we need to recognize `.insert` entities and reconstruct them as `DrawnEntity` instances with a `.insert` shape rather than ignoring or exploding them.

```swift
// Inside MarkupStore.drawnEntities(in:layerId:):
// Identify if the header type is .insert and map to:
// DrawnEntity(shape: .insert(blockName: name, position: pos, scale: scale, rotationDeg: rot))
```

### 2.3 Extend `DXFWriter.swift` records-generation
In `DXFWriter.swift` (`records(for:handle:modern:)`), we need to add a switch case for `.insert` that generates the appropriate DXF group codes for an `INSERT` entity.

An `INSERT` entity in DXF format requires:
- `0\nINSERT`
- `5\n[handle]` (if modern)
- `100\nAcDbEntity` (if modern)
- `8\n[layerName]`
- `62\n[aci]`
- `100\nAcDbBlockReference` (if modern)
- `2\n[blockName]` (the block/symbol name)
- `10\n[x]` / `20\n[y]` / `30\n0.0` (insertion point)
- `41\n[scaleX]` / `42\n[scaleY]` / `43\n[scaleZ]` (scale factors, optional if 1.0 but standard to output)
- `50\n[rotationDeg]` (rotation angle in degrees, optional if 0.0 but standard to output)

*Note:* Standard DXF output uses group code `2` for block name, `10`/`20`/`30` for insert coordinates, `41`/`42`/`43` for scale, and `50` for rotation.

## 3. Impact & File Modifications List

Here are the files we propose to modify (and verify in detail) to implement true block INSERT writing:

### 1. `Sources/CADCore/DXFWriter.swift`
- **Change:** Add `case insert(blockName: String, position: CGPoint, scale: CGPoint, rotationDeg: Double)` to `DrawnEntity.Shape`.
- **Change:** Support the new `.insert` case in `DrawnEntity.translated(by:)`.
- **Change:** Support the new `.insert` case in `DrawnEntity.transformed(by:)` by mapping insertion position and updating scales/rotations correctly.

### 2. `Sources/DWGViewer/MarkupStore.swift`
- **Change:** In `MarkupStore.shape(for:at:store:)`, handle the `.insert` case. Retrieve block names from the `store` payload and build `.insert(blockName:name, position:pos, scale:scale, rotationDeg:rot)`.
- **Change:** Ensure `MarkupStore.prototype(for:layerId:store:)` handles compiling a `.insert` `DrawnEntity` back to an `EntityPrototype` for round-trip reliability.

### 3. `Sources/DWGViewer/DXFWriter.swift`
- **Change:** In `records(for:handle:modern:)`, implement the switch case for `.insert(let blockName, let pos, let scale, let rotationDeg)` to emit DXF group codes conforming to AutoCAD standards.

### 4. `Tests/DWGViewerTests/MarkupStoreTests.swift`
- **Change:** Add unit tests verifying `DrawnEntity` round-tripping for the new `.insert` shape, ensuring that blocks are correctly saved, retrieved, and exported via `DXFWriter` without being exploded.

---

## 4. Verification Plan

1. **Verify Swift Compilation:** Run `swift build` on NovaCAD to ensure that the modifications to `DrawnEntity`, `MarkupStore`, and `DXFWriter` compile successfully.
2. **Verify Tests:** Run `swift test` on NovaCAD to confirm that all existing unit tests (including rendering, editing, and round-tripping) remain green.
3. **Round-Trip Testing:** Specifically run the updated/new tests in `MarkupStoreTests.swift` and `RoundTripTests.swift` to verify that an inserted stamp remains an `INSERT` entity after being exported and re-imported, confirming that it does not explode to markup line segments.
